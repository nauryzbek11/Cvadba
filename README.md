# Самат & Балнұр — свадебное приглашение

Готовый Node.js-сайт для GitHub и Render: конверт, фоновое видео, музыка, ИИ-фото, анкета и закрытый список ответов.

## Запуск на компьютере

Установите Node.js 24. Откройте терминал в папке проекта:

```sh
npm ci
npm start
```

Откройте http://localhost:3000. Для остановки сервера нажмите Ctrl+C.
Локальный пароль находится в файле .env (он не загружается в GitHub). При новом клонировании скопируйте .env.example в .env и задайте ADMIN_PASSWORD.
Прямое открытие index.html подходит только для просмотра: сервер нужен для анкеты и списка гостей.

## Медиа

- Ваше видео: assets/video/background.mp4 — играет на общем фоне без звука с повтором.
- Ваша музыка: assets/audio/music (2).mp3 — музыка загружается и включается после первого касания или нажатия клавиши, чтобы не замедлять открытие сайта. Кнопка-пластинка включает и выключает музыку; после ручного выключения она сама не включается.
- Готовые ИИ-фото: assets/wedding-rings.png, wedding-hands.png, wedding-table.png.

Папка личных фото удалена. Все пути настраиваются в wedding.js. Браузер может приостанавливать видео в фоновой вкладке; при возвращении предусмотрен повторный запуск.

## Ответы и список гостей

Внизу приглашения расположен раздел «Қонақтар тізімі». Введите пароль из ADMIN_PASSWORD: появятся все ответы, участие, число и имена сопровождающих, дата ответа. Кнопки позволяют обновить список, скачать CSV для Excel и выйти.
Пароль проверяется сервером. Без входа ответы недоступны. Сессия длится 8 часов, после перезапуска сервера нужно войти заново. Данные при этом остаются. Пароль не включён в клиентский JavaScript и архив для GitHub.

При повторном открытии сайта список автоматически загружается, если сессия ещё действует. После окончания сессии введите пароль снова — сохранённые ответы появятся. У гостя в том же браузере восстанавливаются заполненная анкета и отметка об успешной отправке; повторная отправка неизменённого ответа не создаёт дубликат даже после перезагрузки страницы.

Ответы записываются в DATA_DIR/guests.jsonl, локально — data/guests.jsonl. Повтор одной отправки с тем же идентификатором не создаёт дубликат. Изменённая анкета сохраняется отдельной записью: список показывает историю всех ответов. Успех отображается только после записи на диск. Для экспорта через терминал также есть `npm run export-guests`.

## GitHub

1. Создайте репозиторий и загрузите содержимое архива github-render-ready.zip, предварительно распаковав его. Сам ZIP загружать не нужно.
2. Проверьте, что в корне есть package.json, package-lock.json, server.js и render.yaml; также загрузите папку .github.
3. .env и data не публикуйте: они исключены через .gitignore и из архива.

Можно загрузить проект через Git. Создайте пустой репозиторий GitHub без автоматически добавленных README и лицензии, затем выполните в папке проекта:

```sh
git init -b main
git add .
git status
git commit -m "Prepare wedding invitation for Render"
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

Замените YOUR_USERNAME и YOUR_REPOSITORY своими значениями. Если Git попросит имя и email автора коммита, задайте свои данные в настройках Git. Не добавляйте .env или data принудительно через git add -f.

Для последующих изменений:

```sh
git add .
git commit -m "Update invitation"
git push
```

GitHub хранит код. GitHub Pages не запускает сервер этого проекта. Для работающей анкеты используйте Render.
В .github/workflows/check.yml настроены проверки при push и pull request.

## Render

1. В Render выберите New → Blueprint и подключите репозиторий.
2. Render прочитает render.yaml. Конфигурация создаёт Node.js Web Service на плане Starter с постоянным диском 1 GB.
3. В запрошенной переменной ADMIN_PASSWORD укажите пароль для списка гостей, согласованный при настройке сайта.
4. Проверьте стоимость в Render перед созданием сервиса, затем запустите размещение.
5. Откройте адрес onrender.com, отправьте пробную анкету и проверьте её в списке внизу.

Настройки уже указаны: build npm ci; start npm start; HOST=0.0.0.0; NODE_ENV=production; DATA_DIR=/var/data; health check /health. Диск подключён к /var/data — ответы сохраняются после перезапуска и обновления сайта. Диск используется одним экземпляром сервера.

| Параметр | Значение |
| --- | --- |
| Тип | Web Service / Node |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/health` |
| Постоянный диск | `/var/data`, 1 GB |
| `DATA_DIR` | `/var/data` |
| `ADMIN_PASSWORD` | Ваш пароль, задаётся только в Render |

Если после развёртывания вход не работает, проверьте ADMIN_PASSWORD в Render → Environment. После изменения переменной перезапустите сервис. Если обновления не появились, откройте Deploys и проверьте успешное завершение последнего деплоя.

Важно: Render Free не поддерживает постоянный диск. Нельзя просто переключить этот вариант на Free, иначе сохранность ответов после перезапуска не обеспечивается. Документация: https://render.com/docs/disks и https://render.com/docs/blueprint-spec.
Сайт и репозиторий автоматически не публиковались. Локальные старые ответы, если они есть, не переносятся на Render автоматически; их нужно перенести отдельно в постоянный каталог. Регулярно сохраняйте CSV или резервную копию данных.

## Проверка

`npm test` проверяет запись ответов, сохранность после перезапуска, защиту списка паролем, выход, ограничение попыток входа, CSV, изображения, аудио/видео и частичную загрузку медиа.
